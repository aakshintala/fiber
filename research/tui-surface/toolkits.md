# TUI toolkit survey: capabilities vs. build

Fact-finding for the Fiber TUI decision (stay in Rust/ratatui+crossterm, or a separate-process TUI in another language). All facts below are from primary sources (docs, READMEs, crates.io/npm/pkg.go.dev/PyPI, GitHub) as of 2026-09-27, cited inline. Where I could not verify a claim from a primary source, it says "not found" and names where I looked.

## Rust: ratatui + crossterm

- **Distribution:** static single binary, no runtime. Probe below: 432 KB stripped release binary for a "hello" ratatui+crossterm app.
- **Idle behaviour:** immediate-mode; the app owns the loop and it blocks on `event::read()` between frames — no built-in ticker (confirmed by probe: 0 idle wakeups sampled, 0.0% CPU over a 10 s idle window). Ratatui's own docs describe the loop as caller-driven redraw-on-change ([FAQ](https://ratatui.rs/faq/), [rendering concepts](https://ratatui.rs/concepts/rendering/)).
- **Maturity:** 20,000+ GitHub stars (grew from the 2023 `tui-rs` fork) per a third-party writeup ([Starlog](https://starlog.is/articles/developer-tools/ratatui-ratatui/)); crates.io shows latest `ratatui` = 0.30.2, released ~3 months before 2026-09-27 (≈ late June 2026), MIT licensed, MSRV 1.88 ([crates.io/crates/ratatui](https://crates.io/crates/ratatui)).
- **Agent TUIs on it:** **codex** (OpenAI) — `codex-rs/tui` depends on ratatui/ratatui-macros directly, confirmed by reading `codex-rs/tui/Cargo.toml` from `https://raw.githubusercontent.com/openai/codex/main/codex-rs/tui/Cargo.toml` (dependency bump commit also visible: [ratatui-macros 0.6→0.7](https://github.com/openai/codex/actions/runs/21807146354)).
- **Ecosystem crates checked:** `tui-scrollview`, `tui-widget-list`, `tui-textarea` (and the `ratatui-textarea` fork), `tui-markdown`, `ansi-to-tui`, `syntect`+`syntect-tui`, `tui-realm`, `hyperrat` — see table for status of each. Full curated list: [ratatui/awesome-ratatui](https://github.com/ratatui/awesome-ratatui) and the official [third-party widgets showcase](https://ratatui.rs/showcase/third-party-widgets/).

### Local probe (macOS arm64, Darwin 25.6.0, cargo 1.98.1/rustc 1.98.1)

Built at `/private/tmp/.../scratchpad/tui-probe/rust`: a minimal ratatui+crossterm app (`ratatui = "0.30"`, `crossterm = "0.29"`, release profile `opt-level=z, lto=true, strip=true`).

- Binary size: **432 KB** (438,400 bytes on disk).
- Peak memory footprint after 10 s idle (measured with `/usr/bin/time -l` on the binary, run under a real pty via `script` so crossterm's raw-mode init succeeds): **1,048,888 bytes ≈ 1.0 MiB peak memory footprint**, 0 page faults, 4 involuntary context switches, 0 voluntary switches over the run.
- Idle wakeups: sampled mid-run with `top -l 2 -pid <pid> -stats pid,cpu,idlew`: **IDLEW = 0, 0.0% CPU** — the process was fully parked in a blocking read, no periodic wakeups.

## Go: Bubble Tea + Charm ecosystem

- **Bubble Tea v2:** release-candidate stage as of this pass, with `v2.0.10` tagged 2026-09-24 ([releases](https://github.com/charmbracelet/bubbletea/releases/tag/v2.0.10)); introduces Mode 2026 synchronized output and a rewritten mouse API (`MouseClickMsg`/`MouseReleaseMsg`/`MouseWheelMsg`/`MouseMotionMsg`) ([v2 alpha discussion](https://github.com/charmbracelet/bubbletea/discussions/1156)). `charm.land/bubbletea/v2` requires Go 1.25+.
- **bubbles:** `viewport` (scrolling, mouse-wheel), `textarea` (multi-line, unicode, scrolling), `list` — all first-party ([bubbles README](https://github.com/charmbracelet/bubbles/blob/main/README.md)).
- **lipgloss:** layout/styling, `JoinHorizontal`/`JoinVertical` for panels+splits, `Style.Hyperlink()` for OSC 8 (built on termenv) ([lipgloss issue #220](https://github.com/charmbracelet/lipgloss/issues/220)).
- **glamour:** stylesheet-based markdown renderer; `glow` (its CLI) has an in-progress "streaming architecture" PR for incremental LLM-style output ([glow PR #823](https://github.com/charmbracelet/glow/pull/823)).
- **Distribution:** Go compiles to one static binary, no runtime — this is Go's baseline behaviour, not something these libraries add.
- **Idle behaviour:** Bubble Tea is described as "a functional, event-driven approach" (Elm architecture) — not independently verified against source for a hidden ticker in this pass; treat as likely event-driven but unconfirmed by direct source read.
- **Maturity:** `charmbracelet/bubbletea` — 45.1k GitHub stars, MIT licence, latest tag v2.0.10 (2026-09-24).
- **Agent TUIs on it:** **crush** (Charm's own coding agent) — `go.mod` requires `charm.land/bubbletea/v2 v2.0.8` plus `bubbles`, `catwalk`, `glamour`, `lipgloss`, confirmed via web search of [charmbracelet/crush/go.mod](https://github.com/charmbracelet/crush/blob/main/go.mod) (not directly fetched this pass — flagging as search-sourced, not a raw file read). The older Go-based `opencode-ai/opencode` fork (a legacy/community fork, distinct from the current `anomalyco/opencode`) also used `bubbletea v1.3.5` per [its go.mod](https://github.com/opencode-ai/opencode/blob/main/go.mod).

## TypeScript/JS: Ink

- **Ink:** ~35.6k GitHub stars; releases up to v7.1.1 (2026-07-16) reported by third-party release trackers ([newreleases.io](https://newreleases.io/project/github/vadimdemedes/ink/release/v7.1.1)) — primary GitHub releases page is [vadimdemedes/ink/releases](https://github.com/vadimdemedes/ink/releases). MIT licensed (per repo).
- **Capabilities:** React-for-terminal via Yoga flexbox layout (native fixed-width panels/splits), `useFocus`/`useFocusManager` for focus, `<Static>` for permanent scrollback output, `<Link>` for OSC 8 with fallback. No first-party virtualized scroll, mouse hit-testing, in-app search, or multi-line editor — all of these exist only as third-party packages (`ink-virtual-list`, `@zenobius/ink-mouse`, none found for search, none found for multi-line input beyond single-line inputs).
- **Distribution:** needs Node (or Bun). Bun can produce a single executable via `bun build --compile`, but it bundles the whole Bun runtime — reported binary sizes are large (a `pkg`-built "hello world" is 30–40 MB; a smaller third-party tool, `bkg`, gets roughly half of Bun's own runtime size by compressing sources) ([bkg README](https://github.com/theseyan/bkg)). Not measured directly this pass — flagged, not probed (see Skipped probes).
- **Idle behaviour:** React-reconciler driven — re-renders happen on state change / stdin events; no evidence of a frame ticker in Ink's docs. Not verified against source in this pass — treat as likely event-driven, unconfirmed.
- **Who uses it:** **gemini-cli** — `packages/cli/package.json` depends on `"ink": "npm:@jrichman/ink@6.6.9"` (a fork), confirmed via [google-gemini/gemini-cli package.json](https://github.com/google-gemini/gemini-cli/blob/main/packages/cli/package.json) (search-sourced, not raw-fetched). **Claude Code** started from Ink but "forked it beyond recognition" — replaced Ink's per-cell object allocation and lack of double-buffering with packed typed arrays and dirty-tracking, while keeping the React-reconciler/Yoga/ANSI shape; this is reported via a third-party source-analysis site ([claude-code-from-source.com, ch.13](https://claude-code-from-source.com/ch13-terminal-ui/)), not an Anthropic primary source — flagged as lower-trust.

## TypeScript/JS: OpenTUI (sst/opentui, now anomalyco/opentui)

- **Repo location:** renamed/moved — `sst/opentui` now redirects to `anomalyco/opentui` (SST rebranded to Anomaly in 2026; confirmed by an HTTP redirect check: `curl -sIL https://github.com/sst/opencode` → `location: https://github.com/anomalyco/opencode`, and search results describing the same rebrand for the org).
- **What it is:** a Zig-implemented renderer with a TypeScript API; you write against it directly or through React/SolidJS/Vue reconcilers ([README via GitHub](https://github.com/sst/opentui/blob/main/README.md)). Ships prebuilt native binaries per platform (darwin/linux/win32 × x64/arm64) loaded via FFI.
- **Capabilities:** `ScrollBox` (virtualized-capable scrolling container), a real mouse-selection model (press/drag/release with click-count-based word/line selection) that writes to the clipboard via OSC 52 on release, configurable Kitty keyboard protocol with a non-blocking "any reply counts as support" detection, focusable `Input`/`Textarea`/`Select`/`ScrollBox` — this is the most complete single ecosystem for the mouse+scroll+clipboard combination that Fiber's TUI needs. See [OpenTUI docs: interaction](https://opentui.com/docs/core-concepts/interaction/), [clipboard](https://opentui.com/docs/core-concepts/clipboard/), [keyboard](https://opentui.com/docs/core-concepts/keyboard/).
- **Distribution:** needs Bun (native addon loaded via FFI); not verified whether `bun build --compile` produces a working single-file OpenTUI binary — not found in docs scanned, would need a direct probe.
- **Idle behaviour:** not found in the docs pages scanned this pass.
- **Maturity:** ~13.2k GitHub stars, MIT licence, `@opentui/core` latest npm version 0.5.12 (reported "4 days ago" from search at the time of this pass).
- **Who uses it:** **opencode** (anomalyco/opencode) — its TUI package `@opencode-ai/tui` depends directly on `@opentui/core`, `@opentui/keymap`, `@opentui/solid` (SolidJS reconciler), confirmed by fetching `packages/tui/package.json` directly: `https://raw.githubusercontent.com/anomalyco/opencode/dev/packages/tui/package.json`. Description on the OpenTUI side: "OpenCode uses OpenTUI in production for millions of users" (search-sourced claim, not independently verified against an OpenTUI primary doc — flagged).

## Python: Textual

- **Maturity:** ~29k GitHub stars, MIT licence, `Textualize/textual` latest release reported as v8.2.4 (2026-04-19) per search ([Textualize/textual/releases](https://github.com/Textualize/textual/releases)) — exact current tag not re-verified by direct fetch this pass.
- **Capabilities:** widget tree with CSS-like layout (native fixed-width panels), built-in focus chain and per-widget mouse events, `TextArea`, `Markdown`/`MarkdownStream` (a *named v4 feature*: streams are coalesced so updates don't outrun the ~20/s append rate, and only the last markdown block re-renders — [Textual v4 "Streaming Release" announcement](https://simonwillison.net/2025/Jul/22/textual-v4/), [Markdown widget docs](https://textual.textualize.io/widgets/markdown/)), `Syntax` widget (Pygments-based, via the `rich` library) for code highlighting.
- **Clipboard:** `App.copy_to_clipboard()` uses OSC 52 ([Darren Burns blog](https://darren.codes/posts/textual-copy-paste/)); notes macOS Terminal.app as a notable non-supporting terminal.
- **Distribution:** needs a Python interpreter — Textual itself ships no compile-to-binary story; would need PyInstaller/Nuitka etc., not documented by Textual itself (not found in Textual's own docs as a first-party path).
- **Idle behaviour:** runs on asyncio; `Timer`/`Animator` classes exist for animations and smooth scrolling, driven by `asyncio.sleep` between ticks ([Textual timer docs](https://lllama.github.io/unofficial-textual-docs/textual/timer.html)); the `Input` widget's `cursor_blink` reactive defaults to `True` ([Textual Input docs](https://textual.textualize.io/widgets/input/)), which implies a periodic timer runs whenever an `Input` is focused — **this means Textual apps are not fully idle-silent by default** the moment a text input has focus. Whether the main message loop itself posts synthetic `Idle` events when the queue is empty (i.e., a secondary polling behaviour) was surfaced in search results describing `_process_messages()` but not confirmed by reading Textual's source directly this pass — flagged as search-sourced, not primary-verified.
- **Who uses it:** not found — no coding-agent TUI (codex/opencode/crush/Claude Code/gemini-cli/pi) was found built on Textual in this pass.

## Other: pi's own TUI, and Zig libvaxis

- **pi (badlogic/pi-mono, `@earendil-works/pi-tui`):** does **not** use Ink, OpenTUI, or any other listed framework. It's a from-scratch TypeScript TUI library with differential rendering and synchronized-output (CSI 2026) updates, main-screen and alt-screen renderers, and native N-API addons per platform for clipboard (`native/darwin`, `native/linux`, `native/win32`). Its only runtime deps are `get-east-asian-width` and `marked` (markdown parsing) — confirmed by fetching `packages/tui/package.json` directly: `https://raw.githubusercontent.com/badlogic/pi-mono/main/packages/tui/package.json`. Source docs: [pi-tui README](https://github.com/badlogic/pi-mono/blob/main/packages/tui/README.md).
- **Zig libvaxis (rockorager/libvaxis):** ~2.0k GitHub stars per search. Notable because its README claims, as first-party features, everything Fiber's list is checking for in one place: RGB colour, OSC 8 hyperlinks, bracketed paste, Kitty keyboard protocol, mouse shapes (OSC 22), system clipboard (OSC 52), and a higher-level `vxfw` framework with an event loop, focus management, and mouse handling ([README](https://github.com/rockorager/libvaxis/blob/main/README.md)). Not independently verified beyond the README claims (no crate/package registry equivalent to check download counts against); flagged as README-sourced only, and Zig is a materially smaller ecosystem/hiring pool than the other four.

## What no ecosystem provides out of the box

- **In-app search with highlighted matches over scrolled content** (capability 3): not found as a first-party feature in *any* of the five ecosystems surveyed (ratatui, Bubble Tea/Charm, Ink, OpenTUI, Textual). Every one of them would need this hand-built.
- **Drag-select-then-clipboard-copy as one wired-up feature**: only OpenTUI ships this as a complete, documented, first-party path (press→drag→release→OSC52). Ratatui, Bubble Tea, Ink and Textual each have the individual primitives (some mouse events, some OSC 52 write call) but the wiring between "user dragged over wrapped text" and "clipboard now has it" is not shown as a built-in in the other four.
- **A single crate/package that does virtualized variable-height scroll + wrap + style + follow-tail together**: every Rust option is one of these properties, not all; Bubble Tea's `viewport` scrolls but doesn't itself virtualize variable-height items; only OpenTUI's `ScrollBox` and Textual's scrollable containers claim the combination, and only OpenTUI documents click-drag selection on top of it.
- **A markdown renderer documented as safe to feed token-by-token while it's still streaming**: Textual is the only one with this as a named, documented feature (v4 "Streaming Release"). Glow/glamour has an in-flight PR for it. Rust's `tui-markdown` explicitly calls itself an experimental proof-of-concept with no streaming story found. Ink and OpenTUI: not found.
