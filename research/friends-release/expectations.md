# What newcomers expect from a coding-agent harness

Research date: October 19, 2026. Recommendation: make the first task safe, recoverable, responsive, and predictably billed before adding more orchestration. Users praise minimal tools, but reject having to assemble familiar workflows themselves. Evidence: [Pi launch discussion](https://news.ycombinator.com/item?id=47143754), [a newcomer who returned to Claude Code](https://www.thevinter.com/blog/bad-vibes-from-pi), and [OpenCode 2.0 first impressions](https://news.ycombinator.com/item?id=50094994).

## Scope and evidence rules

- This is a qualitative, reaction-prioritized sample, not a survey or a measured abandonment rate. I retrieved the top 18 issues created in 2026 in each of the four repositories, sorted by GitHub's `reactions` sort, then searched specific feature titles. I excluded desktop/mobile-only requests from CLI floor counts unless explicitly labeled adjacent evidence. Reproduce the initial queries: [Claude Code](https://github.com/anthropics/claude-code/issues?q=is%3Aissue+created%3A2026-01-01..2026-10-19+sort%3Areactions-desc), [Codex](https://github.com/openai/codex/issues?q=is%3Aissue+created%3A2026-01-01..2026-10-19+sort%3Areactions-desc), [OpenCode](https://github.com/anomalyco/opencode/issues?q=is%3Aissue+created%3A2026-01-01..2026-10-19+sort%3Areactions-desc), [Pi](https://github.com/earendil-works/pi/issues?q=is%3Aissue+created%3A2026-01-01..2026-10-19+sort%3Areactions-desc).
- `N` below counts the distinct linked community reports or discussion threads in that row. It includes missing features and broken implementations of them, not just literal feature requests. Counts are lower bounds within this sample. Reactions are salience, not complaint frequency; never add them to N. Cross-posts of the same incident count once. A source can support multiple rows. Official documentation establishes availability, not demand.
- All community observations used here were published in 2026. Earlier-2026 bugs describe expectations at the time, not proof that today's release still fails. GitHub closure does not by itself prove a fix. For launch reception, “first week” means the first seven days of the linked announcement/publicity thread, not an invented original release date.
- Current baselines: [Claude Code 2.1.303, October 18](https://github.com/anthropics/claude-code/releases/tag/v2.1.303), [Codex CLI 0.163.0, October 15](https://github.com/openai/codex/releases/tag/rust-v0.163.0), and [Pi 1.3.0, October 15](https://github.com/earendil-works/pi/releases/tag/v1.3.0). OpenCode needs two baselines: GitHub's latest release API returned [1.19.3, October 16](https://github.com/anomalyco/opencode/releases/tag/v1.19.3), but its [2.0 announcement](https://anoma.ly/notes/opencode-2-0/) and [V2 installation docs](https://opencode.ai/v2/docs/) are live. I use V2 docs for current V2 behavior, not the older `/docs/` pages.
- HN discussions and written reviews were accessible. Reddit's JSON endpoint returned HTTP 403; I do not quote Reddit text secondhand as if I read it. The 2026-only rule excludes original 2025 launch reviews; later discussion is not a substitute for those first-week records.

## 1. The day-one feature floor

### Ranked demand signals

Ties share a signal tier; their order is judgment, not statistical significance. “Common” means established in the current product interfaces below, not that every harness must copy every command.

| Rank | Capability newcomers notice missing or broken | N | Community evidence and interpretation |
|---|---|---:|---|
| 1 | Predictable token consumption, context and usage visibility | 5 | [Claude quota exhaustion](https://github.com/anthropics/claude-code/issues/16157), [another CLI quota regression](https://github.com/anthropics/claude-code/issues/38335), [cache-cost inflation report](https://github.com/anthropics/claude-code/issues/46829), [OpenCode quota API request](https://github.com/anomalyco/opencode/issues/16017), [MCP context overhead](https://github.com/anomalyco/opencode/issues/8625). These establish demand for predictability and diagnosis, not proof that a cost counter alone fixes billing. |
| 2 | A reliable coding loop with bounded failures | 4 | [Claude instruction/completion failures](https://github.com/anthropics/claude-code/issues/42796), [Pi stuck on Working](https://github.com/earendil-works/pi/issues/4945), [OpenCode memory megathread](https://github.com/anomalyco/opencode/issues/20695), [Pi long-session CPU growth](https://github.com/earendil-works/pi/issues/7730). Quietly hanging or degrading is more damaging than a missing optional integration. |
| 3 | Understandable permissions without repeated interruptions | 4 | [Claude repeated cd approvals](https://github.com/anthropics/claude-code/issues/28240), [compound-command rules](https://github.com/anthropics/claude-code/issues/16561), [OpenCode auto-approval flag request](https://github.com/anomalyco/opencode/issues/8463), [Pi newcomer's demand for path/command restrictions](https://www.thevinter.com/blog/bad-vibes-from-pi). Both autonomy and restrictive operation have constituencies. |
| 4 | Stable rendering, ordinary copy/paste, inspectable input | 4 | [Flicker discussion](https://news.ycombinator.com/item?id=46699072), [Claude copied whitespace](https://github.com/anthropics/claude-code/issues/18170), [OpenCode collapsed paste](https://github.com/anomalyco/opencode/issues/8501), [Claude collapsed paste](https://github.com/anthropics/claude-code/issues/23134). Basic terminal behavior is product functionality, not polish. |
| 5 | Saved sessions, usable resume, accessible older context | 4 | [Claude resume discovery](https://github.com/anthropics/claude-code/issues/26123), [resume after moving/deleting a directory](https://github.com/anthropics/claude-code/issues/28745), [history after compaction](https://github.com/anthropics/claude-code/issues/27242), [OpenCode state restoration complaints](https://news.ycombinator.com/item?id=47461500). Preserving a JSONL file without a working UI does not satisfy this expectation. |
| 6 | A clear, permitted sign-in path for an existing subscription or key | 3 | [Max/OpenCode rejection](https://github.com/anthropics/claude-code/issues/17118) and its [OpenCode cross-post](https://github.com/anomalyco/opencode/issues/7410) count once; [Pi “can I use my Codex plan?”](https://news.ycombinator.com/item?id=47145102); [oh-my-pi OAuth/banning concern](https://news.ycombinator.com/item?id=49007232). Never imply that one vendor's paid plan works in any third-party harness. |
| 7 | Low-friction installation and native packaging conventions | 3 | [Pi XDG request](https://github.com/earendil-works/pi/issues/534), [Pi Nix request](https://github.com/earendil-works/pi/issues/2310), [OpenCode V2 installer taking minutes](https://news.ycombinator.com/item?id=50095874). Different packaging routes matter; supporting every package manager is not established as a universal floor. |
| 8 | Deliberate planning and visible progress | 3 | [Pi launch confusion about no plan mode](https://news.ycombinator.com/item?id=47144965), [OpenCode plan-to-build handoff](https://github.com/anomalyco/opencode/issues/13271), [Codex auto-answering plan questions after 60 seconds](https://github.com/openai/codex/issues/28969). This is stronger evidence for controllable planning than for a mandatory native todo widget. |
| 9 | Screenshot/image input without a save-to-disk detour | 2 | [Windows clipboard request](https://github.com/anthropics/claude-code/issues/26679), [Windows image-paste regression](https://github.com/anthropics/claude-code/issues/32791). Conditional on a vision-capable model and terminal. Image generation is a different feature and is not counted. |
| 10 | Subagents or parallel investigation for existing power-user workflows | 2 | [Pi migration review](https://www.thevinter.com/blog/bad-vibes-from-pi), [OpenCode agent-teams request](https://github.com/anomalyco/opencode/issues/12661). Important to this segment, but Pi's positive reception disproves a universal requirement for a complex team system. |
| 11 | Familiar project instructions | 1 | [Claude AGENTS.md request](https://github.com/anthropics/claude-code/issues/31005). One counted 2026 thread with 564 reactions; its references to older requests are not extra evidence units. High migration value despite a small count. |
| 12 | Undo that protects real files, not just conversation history | 1 | [Codex “Please make /undo back”](https://github.com/openai/codex/issues/9203), 538 reactions. High severity despite one report: untracked files and uncommitted edits are exactly where “just use Git” disappoints. |
| 13 | Discoverable slash commands and skills | 1 | [OpenCode /skills request](https://github.com/anomalyco/opencode/issues/7846), 120 reactions. The expectation is discovery and quick invocation, not a requirement to clone every competitor command. |
| 14 | MCP that connects without consuming the whole context | 1 | [OpenCode deferred MCP search request](https://github.com/anomalyco/opencode/issues/8625), 85 reactions. Direct evidence here concerns usable MCP, not widespread complaints that every harness lacks native MCP. |
| 15 | Integrated diff review | 0 direct CLI; 2 adjacent | [Claude VS Code review UI request](https://github.com/anthropics/claude-code/issues/33932), [Codex VS Code diff crash](https://github.com/openai/codex/issues/35058). Do not count these as CLI complaints. Current CLI implementations nevertheless establish a strong migration convention. |

This ranking would look very different if it simply followed reactions: Claude's removed `/buddy` attracted [2,115 reactions](https://github.com/anthropics/claude-code/issues/45596), and Codex's Linux desktop request [1,464](https://github.com/openai/codex/issues/11023). Neither establishes a terminal harness's essential first-release scope.

Inference: slash discovery, persistence, project instructions, screenshots, usage visibility, and inspectable edits are migration conventions. Native MCP is now documented across all four, but plan mode, approval philosophy, and file undo remain differentiators, not universal parity. The linked product matrix is the evidence; it does not prove how often newcomers demand each feature.

## 2. Abandonment reasons and complaints

Ranked by the combined severity and repetition above, not an invented churn percentage. Quotes preserve the author's wording. Reports remain allegations unless a maintainer/release confirms them.

| Priority | Reason | Quote and evidence | Implication for Fiber |
|---|---|---|---|
| 1 | Cannot trust the work or completion claim | “Claude has regressed to the point it cannot be trusted to perform complex engineering.” [Claude #42796](https://github.com/anthropics/claude-code/issues/42796), April 2, 3,286 reactions. Report lists ignored instructions and false completion. | Show actual tool outcomes and failures. Do not market harness reliability as a guarantee of model correctness. |
| 2 | An existing paid account stops working | “Blocking use of Max plan with Opencode will almost certainly result in me downgrading or cancelling outright.” [Claude #17118](https://github.com/anthropics/claude-code/issues/17118), January 9, 1,415 reactions; [OpenCode #7410](https://github.com/anomalyco/opencode/issues/7410), 420 reactions, same incident. | Publish a supported-subscription matrix before the install command. Distinguish API billing from subscription access. |
| 3 | Surprise quota exhaustion or token burn | “Never hit usage limits in the last three months. Now hitting usage limits after 2 hours.” [Claude #16157](https://github.com/anthropics/claude-code/issues/16157), January 3, 726 reactions. Another CLI report says [1–2 hours on an unchanged workload](https://github.com/anthropics/claude-code/issues/38335), March 24, 545 reactions. Adjacent desktop evidence: Codex user reports [budget draining in 2–3 prompts](https://github.com/openai/codex/issues/28879), June 18, 561 reactions; not a CLI-only finding. | Show context, cache behavior, usage and quota reset times where available; label dollar estimates versus real bills. |
| 4 | Familiar workflows require a configuration project | “I went back and immediately renewed my claude sub.” [Pi newcomer's HN comment](https://news.ycombinator.com/item?id=47145760), February 25; [full February 23 review](https://www.thevinter.com/blog/bad-vibes-from-pi) documents subagent configuration, unexpected model choices, permission setup and an extension's startup update check. Same author, one evidence unit. | Do not answer every missing default with “write an extension.” Separate core, first-party defaults and community-package guarantees. |
| 5 | Flicker, scrolling and copy/paste break ordinary work | “THANK YOU! that flickering is giving me a headache.” [HN comment](https://news.ycombinator.com/item?id=46700144), January 21. A Claude renderer engineer reports a [new differential renderer shipped that day](https://news.ycombinator.com/item?id=46701013). The [copy/paste whitespace report](https://github.com/anthropics/claude-code/issues/18170) has 300 reactions. | Test long output, selection, resize, terminal scrollback and clipboard—not only static screenshots. January flicker is historical, not proof today's version still flickers. |
| 6 | Permissions repeatedly ask the wrong question | “The cd:* prompt keeps appearing and cannot be whitelisted for the session, making the workflow unusable.” [Claude #28240](https://github.com/anthropics/claude-code/issues/28240), February 24, 209 reactions. [OpenCode #8463](https://github.com/anomalyco/opencode/issues/8463), 94 reactions, explicitly requests familiar autonomous behavior. | Remember scoped decisions and explain why an operation is blocked. Neither endless prompts nor unrestricted execution is a universally accepted default. |
| 7 | Hanging looks like expensive work, with no recovery path | “stuck on `Working...` with no streamed text, no tool call, and no visible error.” [Pi #4945](https://github.com/earendil-works/pi/issues/4945), May 24, 35 reactions. [OpenCode state report](https://news.ycombinator.com/item?id=47461500) says agents randomly get stuck, especially in long/nested sessions. | Surface connection versus reasoning versus tools, elapsed time, bounded retries, cancellation and resume. Avoid a forever spinner. |
| 8 | History is technically saved but practically inaccessible | “Session data is NOT lost — `.jsonl` files are intact on disk — but there is no working UI to access them.” [Claude #26123](https://github.com/anthropics/claude-code/issues/26123), February 16, 60 reactions; [post-compaction audit failure](https://github.com/anthropics/claude-code/issues/27242), 91 reactions. | A session picker, search and readable retained history are part of durability. A raw file is not the recovery UX. |
| 9 | Install/startup delay and resource growth undermine “small harness” claims | “The installer took 6 minutes to reach 10%.” [OpenCode V2 first-day report](https://news.ycombinator.com/item?id=50095874). Pi reviewer describes [an extension running an npm check on every launch](https://www.thevinter.com/blog/bad-vibes-from-pi). Pi user reports [50–110% CPU in long sessions](https://github.com/earendil-works/pi/issues/7730), August 6, 14 reactions. | Do not block first paint on network checks. Measure the default installation plus child processes; do not blame every delay on the model. |
| 10 | Security/process changes arrive as a surprise | “the sandbox that i use to wrap the TUI process quietly became useless.” [OpenCode 2.0 first-day comment](https://news.ycombinator.com/item?id=50095629). Codex's [October 12 daemon discussion](https://news.ycombinator.com/item?id=50060694) includes both support for automatic updates and strong opposition to persistent, self-updating background processes. | State where tools execute and what remains running. Offer a documented external sandbox path and explicit service/update controls. |

Cost comparisons need restraint. A [May 18 same-model payload comparison](https://c-daniele.github.io/en/posts/2026-05-18-coding-harness-comparison/) captured 28,407 input tokens for Claude Code, 12,374 for OpenCode and 2,768 for Pi on a cold “hello.” It also explains why prompt caching can reverse the apparent price advantage. This is a dated, single-task experiment through Bedrock/LiteLLM, not a current speed, quality, or all-task cost benchmark.

Authentication errors are an acquisition problem before they become a coding problem. A [March signup report](https://github.com/anthropics/claude-code/issues/34229), 891 reactions, quotes “Unable to send verification code to this number. Try a different number or try again later.” It explicitly concerns general Claude signup, not a CLI-specific defect; use it as adjacent evidence for actionable auth errors, not a CLI demand count.

Security communication can dominate a launch. On October 17, an [OpenCode announcement](https://twitter.com/opencode/status/2111516673953935833) prompted a [175-comment HN discussion](https://news.ycombinator.com/item?id=50133401). A [quoted team notification](https://news.ycombinator.com/item?id=50133412) says third-party provider keys saved in a workspace “may have been exposed” through unauthorized access to a legacy system. I could read the HN reproduction, not independently verify the full incident. Do not infer that every locally stored CLI key leaked; discussion explicitly questions the affected hosted-console scope.

Inferred acceptance test for Fiber: one documented install command, a version check, clear supported systems, a working login, a first safe task, an inspectable diff, and a successful quit/resume. Provide one supported upgrade path and version pin/rollback instructions. This matches the four quickstarts above; it does not imply everyone wants silent updates. The [Codex daemon disagreement](https://news.ycombinator.com/item?id=50060694) is direct counterevidence to that assumption.

Do not demand Homebrew, npm and automatic updates before a friends release. Do demand explicit prerequisites, install location/PATH repair and an uninstall/data-retention explanation: these are concrete details in [Claude setup](https://code.claude.com/docs/en/setup), [OpenCode CLI](https://opencode.ai/v2/docs/cli/) and [Pi quickstart](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/quickstart.md).

## 4. What early launch reception rewarded and punished

### Pi's February 24 publicity week

The [February 24 HN thread](https://news.ycombinator.com/item?id=47143754) reached 608 points and 306 comments. This is a prominent 2026 discovery event, not Pi's original release. These comments were posted within its first two days:

- Praise: “a great harness for use with smaller parameter size models” because of its short prompt and small tool set, [February 24](https://news.ycombinator.com/item?id=47144284).
- Praise: extensions can implement planning while still feeling native, [February 24](https://news.ycombinator.com/item?id=47144954). Another user says customization made it their daily driver, [February 25](https://news.ycombinator.com/item?id=47145723); this is an enthusiast's claim, not a retention statistic.
- Confusion: “Does anyone have an idea as to why this would be a feature?” in response to missing built-in plan mode/subagents, [February 24](https://news.ycombinator.com/item?id=47144965). The commenter later understood the extension approach and was willing to try it.
- Anxiety: whether an existing Codex subscription works, [February 24](https://news.ycombinator.com/item?id=47145102), and whether it can run sandboxed, [February 24](https://news.ycombinator.com/item?id=47144838).
- Abandonment: a newcomer renewed Claude after finding the experience “completely alienating,” [February 25](https://news.ycombinator.com/item?id=47145760). Their [February 23 review](https://www.thevinter.com/blog/bad-vibes-from-pi) mixes core design, Kimi behavior and third-party extensions. It cannot fairly establish that all failures originated in Pi core, but it does establish that users judge the assembled experience.

Contemporaneous written praise: Ronacher's [January 31 review](https://lucumr.pocoo.org/2026/1/31/pi/) says it “doesn't flicker,” is reliable, and has powerful session-aware extensions. Its statement that Pi lacks MCP is historical: [Pi 1.3.0 documents native MCP](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/mcp.md). Do not carry that omission forward into a current comparison.

### OpenCode 2.0's October 14 launch week

The [October 14 announcement thread](https://news.ycombinator.com/item?id=50094994) reached 886 points and 395 comments. Only five days have elapsed at the research cutoff; this is a partial first week. The [official launch](https://anoma.ly/notes/opencode-2-0/) emphasizes a shared service, Code Mode, background subagents/shells, hot-reloaded plugins and an embeddable SDK.

- Praise: “2.0 is a great improvement,” [first-day comment](https://news.ycombinator.com/item?id=50095315). Background subagents and per-subagent model choice were called favorite quality-of-life improvements, [first-day comment](https://news.ycombinator.com/item?id=50095652).
- Praise with friction: a user was happy after upgrading server and clients together, [first-day comment](https://news.ycombinator.com/item?id=50095877). This is evidence for coordinated migration instructions, not frictionless upgrading.
- Panned: the [installer's slow progress rendering](https://news.ycombinator.com/item?id=50095874), [RAM not improving](https://news.ycombinator.com/item?id=50095560), and [the background-service change invalidating an external TUI sandbox](https://news.ycombinator.com/item?id=50095629).
- The launch website itself was called difficult to use, [first-day comment](https://news.ycombinator.com/item?id=50095709). This criticism concerns the announcement page, not evidence that the coding TUI is slow.
- Within three days, the [credential-exposure discussion](https://news.ycombinator.com/item?id=50133401) redirected attention toward trust. Scope remains qualified as described above; do not attach an unverified breach mechanism to V2 itself.

Earlier [March 20 OpenCode publicity](https://news.ycombinator.com/item?id=47460525) drew praise for model choice, local-model fallback, LSP and remote access. It also exposed [session-state instability](https://news.ycombinator.com/item?id=47461500). It was not a first release; those comments are migration evidence, not an original launch-week scorecard.

### Oh-my-pi's July 21 publicity week

The [July 21 HN thread](https://news.ycombinator.com/item?id=48994611), 42 points and 15 comments, is much smaller evidence than Pi's. Within that week, one user praised [easy search integrations](https://news.ycombinator.com/item?id=49000430); another said startup needed no tweaks beyond model selection and felt like a power-user TUI, [July 23](https://news.ycombinator.com/item?id=49022642). A July 22 user instead feared subscription bans after [OAuth refusals](https://news.ycombinator.com/item?id=49007232). The branding of [Windows-native support also confused a Mac reader](https://news.ycombinator.com/item?id=48999389). These are first-week publicity reactions, not proof of an original launch date.

Lesson for Fiber: minimalism earns praise when defaults work and customization is optional. It earns “not for me” when users must rebuild their normal workflow, cannot tell which account pays, or discover an unexpected security/process model. That is the contrast between the linked Pi newcomer and enthusiast reports, and between OpenCode V2's feature praise and service-migration complaints.

## Release floors and comparison with Fiber

These lists are recommendations, not a proposal to clone competitors. They prioritize severity and migration cost as well as frequency. Evidence counts reuse section 1's N; `0 direct + 2 adjacent` is deliberately not presented as 2 CLI complaints. Packaging/convention evidence supports a usable setup, not the exact number of guide pages.

### Floor for a friends release

1. Reliable first coding task, visible errors, cancel and bounded retries — evidence count: 4 ([reliability row](#ranked-demand-signals)).
2. A supported login/key path, explicit subscription exclusions and billing identity — evidence count: 3 ([authentication row](#ranked-demand-signals)).
3. Explain permission boundaries, remember decisions, and give an external-isolation recipe — evidence count: 4 ([permissions row](#ranked-demand-signals)).
4. Responsive long-session terminal, clean copy/paste and inspectable input — evidence count: 4 ([terminal row](#ranked-demand-signals)).
5. Automatic persistence, discoverable resume and readable retained history — evidence count: 4 ([sessions row](#ranked-demand-signals)).
6. Visible context/tokens, labeled cost estimates and available quota/reset data — evidence count: 5 ([usage row](#ranked-demand-signals)).
7. Inspectable edits/diff plus an honest recovery contract; never imply chat rewind restores files — evidence count: 1 direct undo report + 2 adjacent diff reports ([recovery and diff rows](#ranked-demand-signals)).
8. Load existing AGENTS.md/CLAUDE.md with clear precedence — evidence count: 1 ([instructions row](#ranked-demand-signals)).
9. Discoverable slash commands and keyboard help — evidence count: 1 ([command-discovery row](#ranked-demand-signals)).
10. One-command install, version check/update/pin, supported-platform statement and a complete first-run guide — evidence count: 3 ([setup row](#ranked-demand-signals)).

### Floor for a public launch

1. All friends-release requirements, with a self-service guide and diagnostics rather than owner-assisted setup — evidence counts: the 10 requirements above, not a summed independent-user total.
2. File recovery for ordinary agent edits, or conspicuous Git-checkpoint guidance and an explicit lack-of-undo warning — evidence count: 1 high-severity report ([Codex undo](https://github.com/openai/codex/issues/9203)).
3. Supported screenshot/image input and a clear terminal/model compatibility statement — evidence count: 2 ([image-input row](#ranked-demand-signals)).
4. Working local/remote MCP, authentication diagnostics and controlled context overhead — evidence count: 1 ([MCP row](#ranked-demand-signals)); current documented availability: 4 of 4 harnesses in the product matrix.
5. An accessible planning/progress workflow; state explicitly if read-only plan mode or native todos are not supplied — evidence count: 3 ([planning row](#ranked-demand-signals)); a todo widget is not independently established as mandatory.
6. Clear service lifetime, update/disable/rollback controls, credential location and incident-reporting scope — evidence count: 2 additional community threads ([OpenCode V2 launch](https://news.ycombinator.com/item?id=50094994), [Codex daemon](https://news.ycombinator.com/item?id=50060694)); this count is separate from section 1's feature rows.
7. Optional subagent workflow for migrating power users, without making setup compulsory for everyone — evidence count: 2 ([delegation row](#ranked-demand-signals)); not a blocker for a deliberately single-agent launch.

Release judgment: the docs describe most compatibility features already. The highest-value work before friends arrive is a delivered first-run guide and honest demonstrations of login, permissions, diff, cost and resume. Before public launch, make the lack of file undo, OS confinement, conventional plan mode and native todos impossible to mistake for supported functionality. The evidence supports explicit contracts and reliable defaults more strongly than another layer of orchestration.
